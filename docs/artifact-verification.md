# 模型文件与加载身份核验

文件名相同不足以确认模型相同。模型发布资料至少应说明模型架构、文件哈希、输入尺寸、颜色空间、缩放方式、归一化、标签顺序和输出决策规则。

## 文件层

对模型文件和标签映射分别计算 SHA-256。模型文件相同而标签顺序不同，仍可能产生错误的业务解释。

启动前校验脚本会检查两个文件的哈希、读取期间的文件状态、标签索引的连续性、标签内容及类别数。它不调用 PyTorch，不执行模型文件中的反序列化代码。

```bash
python scripts/verify_artifact.py \
  --artifact /path/to/model.pth \
  --artifact-sha256 REPLACE_WITH_MODEL_SHA256 \
  --labels /path/to/labels.json \
  --labels-sha256 REPLACE_WITH_LABELS_SHA256 \
  --class-count 2
```

占位符和错误哈希会导致非零退出。上例中的类别数需要按实际模型替换。

训练 checkpoint 可能包含优化器、调度器等状态，体积大于仅推理文件。导出后的文件哈希会发生变化，即使模型参数保持一致。发布资料应同时保留来源文件与导出文件的对应关系，并执行输出回归。

## 进程层

```bash
systemctl show model-api.service \
  --property=MainPID,ExecStart,WorkingDirectory,ExecMainStartTimestamp
```

以运行进程为准检查加载路径、配置覆盖和启动日志，不仅查看磁盘上的模板。需要检查进程环境时，只读取与模型身份有关的白名单字段，避免将完整环境变量写进可分享的输出。

同一模型可以由不同后端代码提供服务。应用版本、模型文件版本和部署配置应分别记录。

## 接口层

健康接口应区分进程存活和模型就绪。能访问接口、获得 HTTP 200 或执行导入，只能证明各自对应的步骤。

如果接口返回模型哈希，需要说明它是在何时、对哪个文件计算的。启动前哈希是检查点，不是运行期间持续不变的证明；应用还应确保实际加载的文件与已校验文件一致，并控制启动后文件的修改。

## 核验记录

核验记录应在受控位置保存文件哈希、标签契约、应用版本、配置版本、检查时间和必要的加载证据。面向外部分享时只提供通用方法和经过审查的摘要，避免直接发布日志或环境变量转储。
